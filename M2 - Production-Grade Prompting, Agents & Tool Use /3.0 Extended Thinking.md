## [Extended Thinking: Turning reasoning on, calibrating effort, and reading it back correctly](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/production-grade-prompting-agents-tool-use/486743/scorm/3k33sihfb1tww)

### 1. Problem Statement

Developers need a way to improve model accuracy on complex multi-step reasoning and multi-tool planning tasks without unnecessarily inflating token costs on simple lookup operations or invalidating stateful agent API calls due to tampered reasoning signatures.

---

### 2. Summary

* **Reasoning Activation & Control:** Extended thinking allows Claude to generate step-by-step reasoning in a dedicated thinking block before outputting the final answer. Reasoning is adaptive and configured via the `thinking` parameter, with depth controlled by the `effort` setting.
* **Deprecated Controls:** The legacy `budget_tokens` control is deprecated; passing it on current model generations triggers an HTTP `400` error.
* **Cost & Task Selection:** Thinking tokens are billed at the exact same rate as standard output tokens. Extended thinking should be applied strategically to multi-step logic, math, and agent planning while avoiding simple tasks like classification, extraction, or format conversion.
* **The Carry-Back Rule:** In multi-turn tool-use conversations, every thinking block—including encrypted/redacted thinking blocks—must be returned to the API unchanged on subsequent turns. Each block contains a signature verifying reasoning integrity; modifying, summarizing, or dropping it causes API request rejection.
* **Default Visibility:** On the newest model generations, the thinking block content is omitted by default in API responses unless explicitly requested via display settings.

---

### 3. Clear & Simple Explanation

Extended thinking acts as a scratchpad where Claude works through hard problems before writing down its final response.

Because every token written on this scratchpad costs money, you should calibrate when to turn it on:

* **Turn effort up:** For hard multi-step problems, math derivations, or agent workflows where Claude needs to plan tool calls in advance.
* **Leave it off:** For routine tasks like extracting fields, classifying text, or changing formatting, where a well-constrained prompt is cheaper and equally accurate.

When building stateful agents that use tools over multiple turns, you must return Claude's thinking blocks back to the API exactly as you received them. Each thinking block is digitally signed. If you edit or delete the thinking block to save context space, the signature check fails and the API will reject your request.

### 4. Real-World Application

**Scenario:** A multi-step Financial Portfolio Rebalancing Agent that evaluates multi-variable risk metrics, checks user constraints, and plans sequential stock order execution via tool calls.

**System Workflow Architecture:**

```
[ User Rebalance Request ]
           │
           ▼
┌────────────────────────────────────────────────────────┐
│  Agent Orchestrator Service                            │
│  - Sets `thinking` parameter = enabled                 │
│  - Configures `effort` level = high                    │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  Anthropic API (Turn 1: Plan & Tool Selection)         │
│  - Model executes adaptive thinking step               │
│  - Generates signed `thinking` block                   │
│  - Returns tool request: `execute_simulated_trade()`   │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  State Manager & Tool Executor                         │
│  - Executes local tool logic                           │
│  - Preserves exact `thinking` block & cryptographic    │
│    signature in conversation state history             │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
┌────────────────────────────────────────────────────────┐
│  Anthropic API (Turn 2: Execution)                     │
│  - Pass back complete history with untouched `thinking`│
│  - API verifies signature match                        │
│  - Completes trade execution & returns final response  │
└────────────────────────────────────────────────────────┘

```

**Implementation Highlights:**

1. **Adaptive Planning:** High effort ensures Claude reasons through trade dependencies before invoking execution tools.
2. **Signature Preservation:** The orchestrator's state store caches the exact `thinking` block returned in Turn 1 and sends it back to the API in Turn 2 to avoid signature mismatches.

### 5. Key Terms Note Section

### Key Technical Terms

* **Extended Thinking:** An API capability that enables Claude to write out step-by-step reasoning in a separate block prior to delivering the final response.
* **Thinking Block:** A distinct block in the API response payload positioned before the final response block that contains the model's intermediate reasoning tokens.
* **Effort Setting:** A configuration parameter used to calibrate the depth and intensity of adaptive reasoning for a given request.
* **Budget Tokens:** A deprecated parameter formerly used to hard-cap thinking output length; specifying this on current model generations returns a 400 error.
* **Carry-Back Rule:** The strict requirement in multi-turn tool interactions that all received thinking blocks must be re-submitted to the API unchanged in subsequent requests.
* **Redacted Thinking Block:** An encrypted thinking block returned by the API that contains encrypted reasoning data; it must be returned untouched like any standard thinking block.
* **Signature:** A cryptographic proof embedded within a thinking block ensuring the reasoning content has not been tampered with or modified client-side.
* **Context Engineering:** The practice of optimizing conversation context window management without stripping required architectural tokens like signed thinking blocks.

--- **Answer Key & Explanations** ---

1. **C** - On the newest Claude model generations, adaptive reasoning depth is tuned using the `effort` setting. The older `budget_tokens` control is deprecated and explicitly returns a 400 error when passed.
2. **A** - Under the carry-back rule, every thinking block returned by the API carries a signature verifying it wasn't tampered with. Editing, summarizing, or dropping thinking blocks breaks signature matching and causes the API to reject the request.
3. **C** - Extended thinking is designed for multi-step logic, math, and dependent planning where reasoning prevents errors. Mechanical tasks like formatting, extraction, or classification do not benefit from thinking tokens and should use constrained prompts instead.
4. **B** - Encrypted redacted thinking blocks operate under the same carry-back rule as standard thinking blocks. Their encrypted contents must be returned to the API untouched on subsequent turns.
5. **B** - Thinking tokens carry the exact same price as standard output tokens. On current model generations, thinking block contents are omitted by default unless a readable summary is explicitly requested via display settings.
