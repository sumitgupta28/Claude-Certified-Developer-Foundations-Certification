# [Production-Grade Prompting, Agents & Tool Use](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/production-grade-prompting-agents-tool-use/486743/scorm/3k33sihfb1tww)

### 1. Problem statement

Proof-of-concept AI applications often succeed on brief, controlled test inputs but fail when deployed to production environments. Production systems must survive unconstrained context growth across long multi-turn sessions, handle massive tool output payloads, recover gracefully from interrupted SSE streams, balance strict latency/cost budgets, and enforce security guardrails on high-impact external actions.

---

### 2. Summary

* **Prompting Craft & Structural Precision**: Moving beyond conversational prompts to production-grade system prompts using strict XML tags (`<context>`, `<instructions>`, `<examples>`), clear negative constraints, and explicit edge-case handling.
* **Extended Thinking Management**: Leveraging thinking budgets to allow Claude to reason through complex multi-step problems prior to generating a final response, while carefully managing token consumption and latency trade-offs.
* **Tool-Use Schema Design & Robustness**: Crafting precise JSON Schemas for tool definitions, handling tool parameter validation errors, mitigating hallucinated tool calls, and sanitizing oversized tool responses before context reinjection.
* **Stream Resilience & State Recovery**: Managing real-time Server-Sent Event (SSE) token delivery, handling partial JSON parsing for streamed tool inputs, and maintaining client-side state during network drops or stream cutoffs.
* **Production Safety & Agent Boundaries**: Implementing Human-in-the-Loop (HITL) confirmation patterns for irreversible external actions, restricting memory scope across turns, and insulating systems against prompt injection attacks.

---

### 3. Clear & Simple Explanation

Deploying an LLM agent to production is like transitioning a driver from a driving simulator to a 24-hour endurance race:

* **Prompting Craft**: Giving the driver a detailed track manual with precise visual markers (XML tags) rather than vague verbal instructions.
* **Extended Thinking**: Giving the driver time to pause and plan their pit strategy before entering a complex turn, making sure they don't burn extra fuel (tokens) overthinking routine straightaways.
* **Tool-Use & Schemas**: Handing the driver a neatly organized toolbox where every wrench is labeled with exact dimensions (JSON schema), so they never reach for the wrong tool or force an invalid fit.
* **Streaming & Resilience**: Maintaining a continuous pit-crew radio stream (SSE) that stays reliable even when driving through tunnels, with backup state logs to resume tracking immediately if the radio signal drops.

### 5. Key Terms Note Section

Building production-grade agentic architectures requires strict adherence to system safety, schema hygiene, and stream management guidelines outlined in [Production-Grade Prompting, Agents & Tool Use](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/production-grade-prompting-agents-tool-use/486743/scorm/3k33sihfb1tww).

**Key Technical Terms**

* **Tool Schema**: A formal JSON Schema definition specifying a tool's name, description, and typed input parameters required for Claude to accurately invoke external functions.
* **Extended Thinking Budget**: A specified token threshold allocated for internal reasoning chains before Claude emits user-facing output tokens.
* **Human-in-the-Loop (HITL)**: A system design pattern requiring explicit user or administrator approval before an agent executes irreversible or high-risk tool calls.
* **Stream Interruption Handling**: Architectural recovery mechanisms (e.g., event ID tracking, client-side reassembly) to handle network socket drops during active Server-Sent Event streams.
* **Context Compaction**: The process of pruning, summarizing, or filtering prior conversation history and tool outputs to prevent token exhaustion during multi-turn agent runs.

### 6. Exam Practice

--- **Exam Practice** ---

1. A production agentic system allows Claude to interact with a database via custom tools. During high-volume multi-turn sessions, database query responses often return several megabytes of raw JSON, leading to rapid context window exhaustion and inflated latency. What is the most effective architectural pattern to solve this issue?

* A) Increase the `max_tokens` parameter on the API call to allow larger outputs.
* B) Enable extended thinking so Claude can compress the database output internally.
* C) Filter, summarize, or truncate raw tool outputs at the application layer before returning them to Claude's context window.
* D) Convert the database tool schema from standard JSON Schema to an unformatted XML string.

---

2. When configuring an agent to perform complex multi-step reasoning using extended thinking, how should a developer balance model performance against latency and API cost?

* A) Set the thinking budget to the maximum context window size for every request.
* B) Set a structured thinking budget aligned to the task complexity, monitoring token usage via evaluation suites (evals).
* C) Disable streaming responses whenever extended thinking is enabled.
* D) Force Claude to skip tool usage while reasoning through prompt instructions.

---

3. An agent is designed to manage customer bank accounts. It includes tools for `check_balance` (read-only) and `transfer_funds` (state-modifying). What design pattern best protects the system against inadvertent or malicious automated transfers?

* A) Injecting a system prompt instruction stating "Never transfer money without asking."
* B) Omitting the parameter descriptions from the `transfer_funds` tool schema.
* C) Removing the `check_balance` tool and combining all operations into a single tool.
* D) Implementing a Human-in-the-Loop (HITL) gate requiring manual user authorization before `transfer_funds` executes.

---

4. During a real-time SSE streaming generation turn where Claude is streaming tool call input arguments, a network drop disconnects the client. What client-side responsibility is required to ensure system consistency?

* A) Re-issuing the original user prompt in a new session with streaming disabled.
* B) Reassembling received partial events, detecting missing end markers, and handling stream recovery or re-execution gracefully.
* C) Clearing all cached tool schemas from local browser memory.
* D) Sending a HTTP DELETE request to invalidate the active API key.

---

5. Why is using strict JSON Schema definitions with explicit property types and descriptions considered a critical requirement for production tool use?

* A) It reduces the base token cost of the system prompt by 50%.
* B) It allows the Claude API to bypass standard system prompt injection filters.
* C) It enables Claude to accurately structure parameters and lowers the rate of hallucinated or malformed tool invocations.
* D) It forces the model to run strictly in synchronous non-streaming mode.

---

--- **Answer Key & Explanations** ---

1. **C** - Returning uncompressed, large tool outputs into the context window causes context bloat and performance degradation. Applications should filter or summarize tool outputs before reinjecting them into the conversation context.
2. **B** - Extended thinking budgets should be tailored to the problem's complexity and validated against evaluation benchmarks to balance reasoning quality against token cost and latency.
3. **D** - High-impact, state-modifying actions (such as transferring funds) should always require Human-in-the-Loop (HITL) verification to prevent unwanted automated execution.
4. **B** - Clients consuming streaming tool calls must track state, detect incomplete JSON parameter payloads caused by drops, and implement appropriate fallback or retry logic.
5. **C** - High-quality JSON Schemas with explicit descriptions provide the model with the necessary constraints to construct valid parameter payloads and reduce tool call errors.
