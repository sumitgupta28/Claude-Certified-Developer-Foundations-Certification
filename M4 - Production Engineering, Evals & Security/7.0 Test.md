--- ANSWER KEY ---

Question 1: A

Explanation: Model selection determines the foundational unit cost structure of a system, while prompt caching optimizes token processing efficiency within that selected model tier.

Question 2: C

Explanation: The Message Batches API trades synchronous, real-time response times for significantly reduced per-token processing costs on high-volume, non-urgent workloads.

Question 3: D

Explanation: Prompt caching requires an exact token-for-token prefix match. Modifying even a single character before the cache breakpoint breaks matching and forces a complete prompt reprocess.

Question 4: B

Explanation: Placing dynamic or frequently changing data within a cached prefix creates cache staleness, where the model processes outdated data for the duration of the cache's time-to-live (TTL) consistency window.

Question 5: A

Explanation: Multi-agent fan-out patterns multiply token consumption significantly across parallel subagent turns while introducing compilation and coordination latency overhead.

Question 6: C

Explanation: Operational observability requires recording input/output token counts, request latency in milliseconds, and error status on every discrete API call to catch cost and latency spikes.

Question 7: D

Explanation: Prompt instructions are probabilistic natural language text and cannot provide deterministic security guarantees against prompt injection attacks or hallucinations.

Question 8: A

Explanation: True security boundaries require deterministic programmatic controls, such as pre-execution hooks that validate file paths and sandbox containers that enforce directory isolation.

Question 9: C

Explanation: In streaming calls, `tool_use` blocks arrive in fragments across sequential server-sent event deltas and must be fully assembled before client-side execution.

Question 10: B

Explanation: The goal of production engineering in the CCDV-F curriculum is to close the gap between local development assumptions and real-world failure modes exposed under live traffic.
