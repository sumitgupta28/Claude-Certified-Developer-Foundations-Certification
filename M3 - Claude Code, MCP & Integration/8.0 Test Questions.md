--- ANSWER KEY ---

Question 1: B

Explanation: A proper accelerator retains core reusable logic while exposing customer-specific parts as documented parameters, bundling both the evaluation suite and the audit log alongside the asset.

Question 2: A

Explanation: Contributing to shared infrastructure requires clearing the review bar: focused code, a runnable example, a test, a statement of assumptions, and confirmed licensing rights prior to technical review.

Question 3: D

Explanation: Moving aliases can introduce upstream model behavior changes overnight without a rollback path. Pinning model IDs cites a fixed edition, ensuring model updates are adopted deliberately.

Question 4: B

Explanation: Platform placement requires measuring total cost per call rather than token price alone. For regulated enterprise customers, compliance is a pass-or-fail constraint that must be raised during initial scoping.

Question 5: C

Explanation: External content retrieved across a trust boundary must be treated strictly as unverified data rather than executable instructions to prevent prompt injection attacks.

Question 6: A

Explanation: A multi-component system is only as secure as its most privileged seam. Every component must be explicitly restricted to the least privilege required for its specific role.

Question 7: D

Explanation: When an integration seam cannot be adequately secured against vulnerabilities, deployment must be halted and escalated to a human owner rather than shipping an uncontained risk.

Question 8: C

Explanation: Evaluation suites and graders act as the deployment gate and performance baseline, bundled alongside the accelerator to prove asset quality and repeatability across environments.
