## Durable project context with CLAUDE.md, rules files, hooks, and subagents

### 1. Problem Statement

Maintaining consistent AI agent behavior, codebase conventions, and safety constraints across multiple developer sessions without bloating prompt context windows or relying on manual prompt repetition is a major challenge in automated software engineering. Without structured context scoping and deterministic enforcement mechanisms, AI coding agents suffer from context dilution, missed constraints, uncoordinated execution, and potential safety violations.

---

### 2. Summary

Claude Code provides four complementary configuration mechanisms to manage durable project context, project knowledge, and execution behavior:

* The **/init command** scans your codebase and generates a starter CLAUDE.md. The generated file is a great baseline but should be validated before using. 
* **CLAUDE.md**: A root-level Markdown file automatically prepended to context at every session launch. It stores universal conventions, build/test commands, and architectural rules. To prevent context window dilution, it must be kept concise, offloading specialized knowledge to Skills or scoped rules.
* **Rules Files (`.claude/rules/*.md`)**: Scoped instruction files that load conditionally based on `paths` globs defined in their YAML frontmatter (e.g., `paths: - "src/db/**/*.sql"`). Subdirectory placement inside `.claude/rules/` is strictly organizational; frontmatter controls scoping. Unscoped rules load globally at session launch alongside `CLAUDE.md`.
* **Lifecycle Hooks**: Event-driven automation scripts configured via `/hooks` or settings files that run deterministically regardless of model decisions.
  * `PreToolUse`: Runs before tool call execution; exiting with code 2 blocks execution and returns stderr as feedback to the agent.
  * `PostToolUse`: Runs after execution to automate side effects like formatting (`Prettier`), running unit tests, or auditing.
  * Other lifecycle events include `UserPromptSubmit`, `Stop`, `Notification`, `SessionStart`, and `SessionEnd`.


* **Subagents**: Specialized assistants executing tasks in isolated, clean-slate context windows.
  * `Explore` and `Plan` built-in subagents skip `CLAUDE.md` and `git status` for rapid, low-cost research.
  * General-purpose subagents load `CLAUDE.md` and repository state.
  * Custom subagents defined in `.claude/agents/` do not automatically inherit skills; required skills must be explicitly listed in their YAML frontmatter.



---

### 3. Clear & Simple Explanation

Managing Claude Code across a complex repository is similar to managing an automated developer workforce:

* **CLAUDE.md** is the core Onboarding Standard Operating Procedure (SOP). Every time a worker starts a session, they read this quick cheat sheet containing basic rules, commands, and project boundaries.
* **Rules Files** are domain-specific technical reference manuals placed in specific tool sheds. Workers only open the Database Manual when they physically walk over to work on database files, keeping their mental space clutter-free the rest of the time.
* **Hooks** are physical safety interlocks and automated assembly lines. A `PreToolUse` hook acts like a badge scanner that physically blocks entry to restricted server rooms if credentials fail, while a `PostToolUse` hook acts like an automated quality control scanner that polishes code immediately after it is generated.
* **Subagents** are external specialist consultants hired for targeted research. They work in a separate conference room on an isolated task so that drafting materials do not clutter the primary workspace desk.

### 4. Real-World Application

**Scenario**: An enterprise financial transaction service requires strict database transaction boundaries, zero unauthorized modifications to core payment configurations, automated code linting/formatting, and rapid codebase exploration without risk of context bloat.

### 5. Key Technical Terms

* **CLAUDE.md**: The root configuration Markdown file loaded prepended into prompt context at session startup to define global rules and conventions.
* **Context Dilution**: The reduction in model adherence to specific instructions caused by an oversized context window containing non-essential information.
* **Rules Files**: Scoped instruction files residing in `.claude/rules/` that dynamically enter prompt context when files matching their YAML frontmatter `paths` glob are accessed.
* **Lifecycle Hooks**: Script triggers bound to agent lifecycle events (`PreToolUse`, `PostToolUse`, `SessionStart`, etc.) executing deterministically independent of model reasoning.
* **PreToolUse Hook**: A lifecycle hook executing before a tool call that can block unauthorized actions by exiting with code 2 and passing error output back to the agent.
* **PostToolUse Hook**: A lifecycle hook executing immediately after tool completion to trigger automated side effects like linting, testing, or audit logging.
* **Subagents**: Specialized assistant sessions executing tasks in isolated contexts without inheriting main conversation history, returning only final summary output.
* **Explore / Plan Built-in Subagents**: Optimized lightweight subagents that skip loading `CLAUDE.md` and repository state (`git status`) to optimize speed and token usage.

### 6. Exam Practice

--- **Exam Practice** ---

1. A developer notices that after adding extensive architectural diagrams and historical change logs to `CLAUDE.md`, Claude Code frequently fails to follow critical test-driven development guidelines listed at the top of the file. What is the primary technical cause of this issue, and what is the recommended architecture pattern to resolve it?

* A) The `/init` command failed to re-index the file; the developer must re-run `/init` to update session priorities.
* B) Context window dilution occurred; non-essential context and large documentation should be moved into load-on-demand Skills or path-scoped rules.
* C) `CLAUDE.md` exceeded the 4KB hard limit, causing Claude Code to truncate the first half of the file at startup.
* D) The file permissions were altered; a `PreToolUse` hook must be configured to dynamically re-inject `CLAUDE.md` on every turn.

---

2. An architecture team wants to enforce a strict rule preventing Claude Code from modifying files in `src/config/production/`. They configure a rule in `.claude/rules/config-rules.md` stating "Never edit production config files," but notice the agent occasionally bypasses the rule during complex refactoring. How should this constraint be implemented to guarantee compliance?

* A) Place `config-rules.md` into `.claude/rules/production/` directory, as subdirectory placement automatically enforces tool execution blocking.
* B) Add `paths: - "src/config/production/**"` to the YAML frontmatter of `config-rules.md` to restrict editing tools.
* C) Implement a `PreToolUse` hook script that inspects tool arguments and exits with code 2 when a restricted path is targeted.
* D) Configure a `PostToolUse` hook that reverts git commits whenever production configuration files are edited.

---

3. You are building a custom subagent in `.claude/agents/reviewer.md` to perform automated security reviews on incoming code changes. The subagent needs to invoke a custom corporate vulnerability scanning skill defined in your project. Which statement accurately describes how custom subagents manage context and skills?

* A) All custom subagents automatically inherit all active session skills and global settings from `CLAUDE.md`.
* B) Built-in agents inherit skills automatically, whereas custom subagents must inherit skills via `PreToolUse` lifecycle hooks.
* C) Custom subagents run in an isolated context and do not automatically see skills; required skills must be explicitly listed in the subagent's YAML frontmatter.
* D) Custom subagents automatically inherit the main session's full conversation history, but strip out `CLAUDE.md` rules to optimize token usage.

---

4. A software engineer uses the built-in `Explore` subagent to investigate a complex bug in a multi-module repository. They expect the `Explore` subagent to adhere to a database safety restriction defined in `CLAUDE.md`, but the subagent ignores it. What explains this behavior?

* A) Built-in `Explore` and `Plan` subagents bypass loading `CLAUDE.md` and `git status` to keep research fast and cost-effective.
* B) Subagents can only parse rules files residing inside `.claude/rules/` and are unable to read root-level Markdown files.
* C) The `Explore` subagent runs with full administrative permissions, automatically overriding all project-level `CLAUDE.md` constraints.
* D) `CLAUDE.md` is only loaded during `PostToolUse` events and is unavailable during initial subagent execution.

---

--- **Answer Key & Explanations** ---

1. **B** - **Context window dilution** occurs when `CLAUDE.md` grows too large, causing any single rule to represent a smaller percentage of loaded context and reducing model adherence. The correct approach is to keep `CLAUDE.md` concise and move large docs/rules into load-on-demand Skills or path-scoped rules files. Option A is incorrect because `/init` generates a starter template, not an index. Option C is incorrect as no 4KB hard truncation rule exists. Option D is incorrect because file permissions do not cause instruction loss.
2. **C** - Instructions in `CLAUDE.md` or rules files are prompt-level guidance. True deterministic enforcement requires a **`PreToolUse` hook** that evaluates target arguments before execution and exits with code 2 to block the action and provide error feedback. Option A is incorrect because subdirectory placement is purely organizational. Option B is incorrect because scoping rules via frontmatter `paths` controls context loading, not execution blocking. Option D is incorrect because `PostToolUse` hooks run after the tool has already executed.
3. **C** - Custom subagents execute in an **isolated context window** and do not inherit the main conversation history or skills. Any required skill must be explicitly declared in the subagent's frontmatter configuration. Option A is incorrect because skills are not inherited automatically. Option B is incorrect as lifecycle hooks do not inject skills into subagents. Option D is incorrect because subagents start from a clean slate rather than inheriting full session history.
4. **A** - Built-in **`Explore` and `Plan` subagents explicitly bypass loading `CLAUDE.md` and `git status**` to prioritize execution speed and token cost efficiency. To enforce `CLAUDE.md` rules during delegated work, developers must use general-purpose subagents or custom subagents. Option B is incorrect as general subagents read `CLAUDE.md`. Option C is incorrect as `Explore` does not override permissions. Option D is incorrect as `CLAUDE.md` loads at session/task launch.
