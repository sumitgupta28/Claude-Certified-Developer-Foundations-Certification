### Coordinating Several Claude Deployments with Trust Boundaries

### 1. Problem Statement

When orchestrating multi-component AI applications—combining API gateways, agentic workflows (such as Claude Code tasks), and Model Context Protocol (MCP) servers—each connection seam introduces vulnerabilities where identity, secrets, and untrusted external inputs cross boundaries. Without strict isolation and privilege scoping, a security flaw or indirect prompt injection in one component can compromise downstream systems across the entire stack.

### 2. Summary

Multi-component architectures expand capability by linking specialized services, but every seam acts as a trust boundary requiring explicit security controls.

* **Trust Boundaries at Integration Seams**: Any transfer of data or execution control between components (e.g., API entry to Claude Code, or Claude Code to MCP server) represents a trust boundary.
* **Handling Untrusted Content**: External data retrieved by agentic processes (Claude Code tasks) must be ingested strictly as raw data downstream, **never as executable instructions**, to prevent indirect prompt injection.
* **Whole-Application Least Privilege**: System security is dictated by its most privileged seam. Every component and MCP server must be scoped strictly to the minimum required access.
* **Compliance & Regulated Deployments**: Regulated enterprise workloads requiring Zero Data Retention (ZDR) or HIPAA Business Associate Agreements (BAA) typically deploy via AWS Bedrock or Google Cloud Vertex AI after verification on [platform.claude.com](https://platform.claude.com).
* **Unresolvable Seams**: When a seam cannot be secured programmatically, deployment must halt and escalate to a human owner rather than shipping around the boundary.

### 3. Clear & Simple Explanation

Think of a multi-component Claude architecture like a secure financial vault:

* **The Front Door (First-Party API)**: Verifies caller identity and checks incoming requests before allowing them inside.
* **The Field Researcher (Claude Code Task)**: Collects documents from the outside world. Even if the researcher is trusted, the papers they bring back could contain malicious fine print. Therefore, the internal team must treat those papers purely as unverified reference material, not corporate orders.
* **The Vault Keyholder (MCP Server)**: Has direct access to internal databases. If given master keys to every room, anyone who tricks the Field Researcher could steal everything. To prevent this, the Keyholder receives access only to specific filing cabinets, and every access attempt is recorded in audit logs.

### 5. Key Terms Note Section

To pass security reviews and maintain enterprise posture, developers must maintain strict boundary scoping across all components.

**Key Technical Terms**:

* **Trust Boundary**: The exact perimeter or seam where data or execution control moves between distinct deployment environments or security contexts.
* **Least Privilege**: The security principle of granting a component or service identity only the minimal privileges required to complete its specific task.
* **Model Context Protocol (MCP) Server**: A standard protocol server used to connect Claude capabilities to internal customer databases or third-party tools.
* **Zero Data Retention (ZDR)**: A compliance tier ensuring prompt and completion data are not stored or logged by the hosting provider after processing.
* **HIPAA BAA (Business Associate Agreement)**: A formal contract allowing health applications to process Protected Health Information (PHI) in compliance with US privacy laws.

5. Which pair correctly matches the multi-component application architecture element to its corresponding trust boundary control?

* A) First-party API: Converts external web content into system instructions.
* B) Claude Code task: Scopes customer database read/write access to root privileges.
* C) MCP server: Scopes system access to least privilege and logs all boundary access.
* D) Customer Database: Orchestrates API requests coming from external end-users.

---

--- **Answer Key & Explanations** ---

1. **C** - Content fetched from external sources by an agentic workflow is untrusted downstream. To prevent prompt injection, receiving components must treat fetched content strictly as data rather than actionable instructions.
2. **B** - Security applies to the application as a whole. An application is only as contained as its most privileged seam; an overly permissive component becomes a weak point that can be steered to access unauthorized resources.
3. **D** - AWS Bedrock and Google Cloud Vertex AI are the primary platforms satisfying regional data residency and compliance needs, provided developers verify ZDR and HIPAA BAA eligibility via [platform.claude.com](https://platform.claude.com) or the Anthropic Trust Center.
4. **A** - When an integration seam cannot be adequately secured, best practices dictate escalating the issue to a human owner rather than attempting to ship around the risk.
5. **C** - According to the multi-component integration framework, an MCP server reaches customer systems on the app's behalf; its primary control is scoping access to least privilege and recording audit logs.
