### Building and configuring an MCP server: transport, scope, and the GitHub server

### 1. Problem statement

Connecting external tools directly into application code creates redundant maintenance, security credential leaks in version control history, and context window bloat across enterprise developer tools. Organizations need a standardized protocol to expose tools, resources, and prompts from dedicated server processes while controlling context costs, transport boundaries, access permissions, and secret management.

---

### 2. Summary

* **MCP Server Fundamentals**: Model Context Protocol separates tool, resource, and prompt definitions from individual applications into dedicated server processes. When connected, [Claude Code, MCP & Integration](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/claude-code-mcp-integration/486744/scorm/173ln01ww7hgd) discovers and invokes these capabilities across sessions.
* **Resources & Prompts**:
  * *Resources*: Read-only data fetched directly into context without tool calls (direct addresses for static data, templated addresses for parameterized data).
  * *Prompts*: Pre-written instruction templates maintained on the server to enforce consistent execution quality.


* **Transports**:
  * *stdio*: Local process communication via standard input/output.
  * *HTTP*: Standard web protocol for hosted remote servers.
  * *SSE (Server-Sent Events)*: Legacy transport superseded by HTTP; deprecated for new implementations.


* **Context Optimization & Caching**:
  * Tool definitions are deferred by default and discovered dynamically via search to save context tokens.
  * Prompt caching reuses stable request prefixes (tools, system prompts) above a 1,024-token threshold using up to four `cache_control: { type: "ephemeral" }` breakpoints. Default TTL is 5 minutes (resets on read); opt-in TTL is 1 hour (`ttl: "1h"`).


* **Retrieval-Augmented Generation (RAG)**:
  * *Classical RAG*: Pre-chunks data into vector embeddings stored in a vector database for similarity lookup before inference.
  * *Agentic Search*: Dynamically searches live sources on demand during runtime without pre-indexed databases.
  

* **Configuration Scopes**:
  * *Local*: `~/.claude.json` under current project path (unshared).
  * *User*: Personal settings across all projects (unshared).
  * *Project*: `.mcp.json` at repository root (committed to git; requires local execution runtimes for `stdio` servers on teammate machines).
  * *Enterprise*: Centrally managed administrator configurations.


* **Permissions & Secrets Security**:
  * Target tools using `mcp__server__tool` syntax; deny rules on specific tools override server-level allows.
  * API MCP connectors use `mcp_toolset` `enabled` flags to control visibility.
  * API keys and tokens must be supplied via environment variables—never hardcoded inside `.mcp.json`, as repository history retains overwritten secrets.



---

### 3. Clear & Simple Explanation

An MCP server works like a universal adapter that lets Claude connect to external software like GitHub, databases, or cloud services.

* **Tools, Resources, and Prompts**: Tools allow Claude to perform actions. Resources let Claude read static or parameterized files directly without wasting steps calling a tool. Prompts are reusable, pre-written instructions stored on the server.
* **Transports**: Local programs on your computer talk to Claude using standard input/output (`stdio`). Remote services hosted in the cloud connect over standard web networks (`HTTP`).
* **Managing Memory Costs**: Loading every tool definition upfront wastes memory tokens. Claude uses search discovery to find tools on demand and uses prompt caching to save identical system prompts or tool schemas for 5 minutes or 1 hour.
* **Scope and Safety**: Project configuration stored in `.mcp.json` lets your entire team share the same tool setup through git. However, secret tokens should always be stored in local environment variables so they aren't accidentally exposed in code repositories.

### 4. Real-World Application

**Scenario**: A financial enterprise requires developers to query internal database records and manage GitHub repositories via Claude Code without exposing API tokens in git repositories or overloading context windows with unused schemas.

**Architecture Flow**:

1. **Scope & Transport**: The team commits a project-scoped `.mcp.json` defining an `HTTP` connection to the remote GitHub MCP server and a `stdio` connection to a local compliance database process.
2. **Security & Permissions**: The developer sets their GitHub Personal Access Token in a local environment variable. Enterprise managed settings enforce a `deny` rule on `mcp__github__delete_repo`.
3. **Execution**: When a developer queries issue data, Claude uses agentic search to discover `mcp__github__list_issues`, leverages prompt caching (1-hour TTL) for the stable tool schema prefix, and retrieves direct resources into context.

### 5. Key Terms Note Section

**Key Technical Terms**:

* **Model Context Protocol (MCP)**: An open standard that separates tool, resource, and prompt definitions from host application code into standalone server processes.
* **Resource**: Read-only data exposed by an MCP server (direct or templated) fetched and placed directly into context without requiring tool calls.
* **stdio Transport**: An inter-process communication transport using standard input/output streams for local server processes.
* **HTTP Transport**: A network transport protocol used to connect MCP clients to remote, hosted MCP servers.
* **Prompt Caching**: A performance feature that caches identical token prefixes (above 1,024 tokens) using `cache_control` breakpoints with 5-minute or 1-hour (`ttl: "1h"`) lifetimes.
* **Classical RAG**: A retrieval architecture that splits documents, builds vector embeddings, and queries a vector database prior to model generation.
* **Agentic Search**: A dynamic retrieval approach where the model searches live data sources on demand during task execution without pre-indexed databases.
* **.mcp.json**: A repository-root configuration file used to define project-scoped MCP servers shared across git clones.
* **mcp__server__tool**: The explicit syntax used in permission rules to target specific individual MCP tools for allow or deny enforcement.

5. A platform engineering team needs to choose between Classical RAG and Agentic Search for two distinct corporate workloads: (Workload 1) Searching a static, 50,000-page historical policy archive, and (Workload 2) Dynamically discovering and fetching relevant tools across 15 newly connected MCP servers in Claude Code. Which alignment correctly matches the retrieval pattern to the workload based on system architecture principles?

* A) Workload 1 uses Agentic Search to avoid upfront embedding costs; Workload 2 uses Classical RAG to pre-index MCP tool definitions into a vector database.
* B) Workload 1 uses Classical RAG to match queries against a pre-indexed vector database; Workload 2 uses Agentic Search to discover and load tools dynamically at request time.
* C) Both workloads should use Classical RAG because Agentic Search cannot scale when source material exceeds context window limits.
* D) Both workloads should use Agentic Search because Classical RAG requires `stdio` transport capabilities not supported by Claude Code.

---

--- **Answer Key & Explanations** ---

1. C - A project-scoped `.mcp.json` file committed to version control distributes the server launch command to all team members. However, for a `stdio` server, the process runs locally on each teammate's workstation. If a teammate lacks the required runtime (e.g., Node/npx), the local subprocess cannot spawn and the server fails.
2. B - Prompt caching requires a minimum threshold of 1,024 tokens (the payload has 2,500 tokens) and supports up to four ephemeral breakpoints. The optional `ttl: "1h"` parameter successfully extends the cache lifetime from the 5-minute default to 1 hour, making it ideal for workloads with longer gaps between requests.
3. D - Permission rules target specific MCP tools using the `mcp__server__tool` syntax. A deny rule on a specific write tool (e.g., `mcp__github__create_issue`) overrides broader server allows, keeping the agent constrained to a narrow operational boundary while maintaining access to read-only tools.
4. B - Committing a secret inline into a version-controlled file writes the token into git history. Overwriting or replacing the secret in a subsequent commit does not remove the earlier commit from the repository history, leaving the token vulnerable to extraction until the secret is rotated and revoked.
5. B - Classical RAG relies on pre-chunking and vector indexing built in advance, making it ideal for static, large-scale document archives (Workload 1). Agentic Search skips upfront indexing to search and fetch live data or tool definitions on demand at request time, which is how Claude Code dynamically manages context cost across connected MCP servers (Workload 2).
