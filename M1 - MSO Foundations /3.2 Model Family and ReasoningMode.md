# [Model options and reasoning modes](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/mso-foundations/486742/scorm/1zuxexjatih0p)

### 1. Problem Statement

Architecting LLM-powered applications requires balancing execution speed (latency), operational cost (token consumption), and task accuracy (quality). Developers often struggle with whether to upgrade base model capacity or enable/adjust reasoning modes, leading to over-spending on large models for simple requests or under-performing with under-configured reasoning on complex tasks.

---

### 2. Summary

* **Orthogonal Control**: Model choice (base capacity tier) and reasoning mode (effort setting) are independent variables configured separately per request.
* **Execution Strategies**:
* **Capable Model + Reasoning OFF**: Delivers fast, direct responses for straightforward tasks with minimal latency.
* **Smaller Model + Reasoning ON**: Consumes additional thinking tokens to handle complex logic without upgrading the base model tier.
* **Capable Model + Higher Effort**: Built for demanding, safety-critical, or complex tasks requiring maximum cognitive capabilities.


* **Trade-off Evaluation**: Systems must continuously weigh cost, latency, and output quality when selecting model and reasoning configurations.

---

### 3. Clear & Simple Explanation

Selecting a model and reasoning mode is like choosing a vehicle and its driving mode:

* **Model Choice** sets the engine size (e.g., a lightweight commuter car vs. a heavy-duty commercial truck).
* **Reasoning Mode** is activating "Precision Mode" (how much time and cognitive effort the model spends deliberating before providing an answer).

Because these two controls are independent:

1. For quick, simple tasks, use a capable model with reasoning turned **off** for direct, ultra-fast responses.
2. To keep base model costs low while solving tricky multi-step problems, take a smaller model and turn reasoning **on**.
3. For the most complex, mission-critical problems, combine a top-tier capable model with a **high effort** reasoning setting.

### 5. Key Terms Note Section

When designing systems using the [MSO Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/mso-foundations/486742/scorm/1zuxexjatih0p) framework, developers must preserve technical precision when managing model parameters and thinking configurations.

**Key Technical Terms**

* **Model Choice**: The selection of a specific model tier based on parameter footprint, intelligence baseline, and default response speed.
* **Reasoning Mode**: An independent API configuration determining whether the model executes explicit internal thinking routines prior to generating a response.
* **Effort Setting**: The control parameter that dictates the depth and token allocation dedicated to the model's reasoning phase.
* **Thinking Blocks**: Standardized data structures returned in the API response that contain the internal tokens generated during the model's reasoning phase.
* **Latency**: The total round-trip time required to process an API request and deliver the final response payload.
* **Cost-Latency-Quality Triad**: The decision-making framework balancing financial budget (token volume), response speed (latency), and answer precision (quality).

5. When reasoning mode is enabled on a smaller model tier, what is the primary operational trade-off during API request execution?

* A) Consuming additional tokens for thinking blocks, trading increased latency and token expenditure for improved reasoning performance.

---

--- **Answer Key & Explanations** ---

1. **A** - A capable model tier with reasoning turned off delivers fast and direct outputs while retaining high base model intelligence.
2. **C** - Because model choice and reasoning mode are independent, pairing a smaller (lower cost) model with reasoning mode enabled allows the system to spend additional tokens on thinking blocks to tackle complex tasks cost-effectively.
3. **D** - The most demanding tasks pair a capable model tier with a higher effort setting to achieve maximum problem-solving performance.
4. **B** - Model choice and reasoning mode are completely orthogonal and independent settings that can be adjusted separately for each API call.
5. **A** - Turning reasoning on for a smaller model spends additional tokens during the thinking phase, increasing latency and token usage to achieve higher cognitive task performance.
