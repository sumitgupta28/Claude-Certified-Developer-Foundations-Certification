# [Prompting modes: zero-shot, one-shot, multi-shot](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/mso-foundations/486742/scorm/1zuxexjatih0p)

### 1. Problem statement

Engineers often over-complicate prompt design by adding lengthy, verbose instructions that fail to fix formatting drift or edge-case failures. Conversely, indiscriminately adding too many worked examples inflates per-call token costs and consumes context budget. The core challenge is balancing prompt size (cost and latency) against response reliability (quality and structural compliance).

---

### 2. Summary

* **Token Cost & Context Budget**: Every example included in a prompt adds input tokens on every API call and consumes valuable context window space.
* **Zero-Shot Applications**: Ideal for simple tasks where the task definition and expected output structure are obvious and easily understood by the model.
* **One-Shot / Multi-Shot Applications**: Recommended when the output requires explicit structural schemas, specific casing, or handling of edge cases that text descriptions fail to enforce.
* **Instruction Efficiency**: Adding 1 or 2 targeted, accurate examples often resolves structural or formatting issues faster and more reliably than writing additional paragraphs of instructions.
* **Minimal Sufficiency Discipline**: The core prompt engineering principle is to construct the smallest, most concise prompt that consistently yields reliable results in production.

---

### 3. Clear & Simple Explanation

Think of sending an API request like paying for postage on a letter where every word costs extra money:

* **Zero-shot** is like sending a quick text message—it's cheap, fast, and works great when the request is clear and straightforward.
* **One-shot and Multi-shot** are like including filled-out sample forms in the envelope. Paying for those extra sample pages (tokens) costs more on every shipment, but it guarantees the recipient formats the final form with the exact layout, casing, and structure you need.
* **Rule of Thumb**: Don't write three long paragraphs explaining how a JSON object should look. Showing 1 or 2 clean examples fixes the issue immediately, saves effort, and gives you a reliable output with the smallest prompt footprint possible.

### 5. Key Terms Note Section

Preserve technical accuracy regarding prompt context management and cost optimization on the [MSO Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/mso-foundations/486742/scorm/1zuxexjatih0p) module.

**Key Technical Terms**

* **Context Budget**: The finite token capacity within an LLM's context window that must be allocated efficiently across system prompts, examples, context, and user queries.
* **Minimal Sufficiency**: The architectural discipline of using the minimum token volume necessary in a prompt to achieve deterministic, production-grade output reliability.
* **Input Token Consumption**: The recurring financial and latency cost incurred by sending prompt context (including instructions and worked examples) to the API on every call.
* **Structural Compliance**: The degree to which an LLM's generated output adheres strictly to expected schemas, keys, casing, and data types without manual intervention.
* **Formatting Drift**: The tendency of an LLM output to deviate from implied or vaguely described formatting rules when concrete in-context examples are absent.

1. **C** - Adding examples to a prompt increases input token count on every single call and uses up context budget, trading higher financial and context cost for better output quality and reliability.
