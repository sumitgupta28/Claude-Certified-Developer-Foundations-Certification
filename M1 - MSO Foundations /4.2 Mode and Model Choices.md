# [Prompting modes: zero-shot, one-shot, multi-shot](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/mso-foundations/486742/scorm/1zuxexjatih0p)

### 1. Problem Statement

Developers face an ongoing trade-off between output quality, inference latency, and API expenditure. Relying exclusively on high-capability model tiers in zero-shot mode can cause excessive API costs, whereas defaulting to lightweight models without structural examples leads to evaluation failures and schema non-compliance.

---

### 2. Summary

* **Interacting Levers**: Prompting mode (zero-shot, one-shot, multi-shot) and model tier selection (e.g., Haiku vs. Sonnet vs. Opus) are complementary levers that should be evaluated together.
* **Capability vs. Examples Trade-off**: A highly capable model often achieves task success in **zero-shot** mode, whereas a smaller model may require **one-shot** or **multi-shot** examples to match the same output structure and quality bar.
* **Cost Optimization via Examples**: Incorporating worked examples into a prompt allows a cheaper, smaller model tier to achieve required performance metrics, optimizing overall token spend.
* **Eval-Driven Selection**: System architects should start with the simplest model tier and fewest examples (zero-shot), using empirical evaluation (eval) benchmarks to guide whether to increase model capability or add in-context examples.

---

### 3. Clear & Simple Explanation

Choosing a prompting mode and a model tier is like assigning a job to a worker:

* **Zero-shot**: Giving instructions without showing completed sample work.
* **One-shot / Multi-shot**: Giving instructions alongside one or more completed sample blueprints.

A senior expert (more capable model) can complete a job correctly zero-shot using instructions alone. A junior assistant (smaller model) might struggle with abstract instructions, but if you show them 2 or 3 completed sample forms, they can perform at the exact same quality level as the senior expert—at a fraction of the operational cost.

Always let test suites (**evals**) drive these choices: start with the cheapest configuration (simplest model + zero-shot) and only add examples or upgrade model tiers where test results show a measurable need.

### 5. Key Terms Note Section

Preserve technical accuracy regarding prompt strategy and model orchestration within the [MSO Foundations](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/mso-foundations/486742/scorm/1zuxexjatih0p) framework.

**Key Technical Terms**

* **Zero-Shot Prompting**: Providing task instructions to an LLM without including completed input-output examples in the context window.
* **Multi-Shot (Few-Shot) Prompting**: Providing task instructions accompanied by two or more worked input-output examples to establish output shape and behavioral boundaries.
* **Model Tier**: The baseline intelligence, size, and cost/latency profile of a selected model family member (e.g., Haiku, Sonnet, Opus).
* **Evaluation (Eval)**: Quantitative benchmark suites used to measure model performance, schema accuracy, and output quality against defined metrics.
* **Complementary Optimization Levers**: The practice of adjusting prompting modes and model selection simultaneously to achieve the optimal cost-quality-latency profile.

--- **Answer Key & Explanations** ---

1. **B** - Adding examples to a smaller model tier (like Haiku) often allows it to match the structural compliance of a larger model, making it the most cost-effective first adjustment before upgrading model tiers.
2. **C** - The core optimization methodology dictates starting with the simplest model tier and fewest examples (zero-shot) evaluated against an eval suite, then escalating capability or adding examples only where the eval demonstrates a need.
3. **D** - In-context examples guide smaller models to adhere strictly to expected schemas and structures, enabling high task accuracy at lower token costs than invoking a higher-tier model zero-shot.
4. **A** - System migrations should always be guided by empirical evaluations (evals). Adding few-shot examples to Haiku and testing it against the eval benchmark verifies if it maintains the required quality threshold before production deployment.
5. **B** - Prompting mode and model choice interact as related levers; adding in-context examples can bridge the structural capability gap for a smaller, lower-cost model.
