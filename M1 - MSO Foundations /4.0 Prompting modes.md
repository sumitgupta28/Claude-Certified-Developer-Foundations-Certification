# [Prompting modes: zero-shot, one-shot, multi-shot](https://anthropic-partners.skilljar.com/path/claude-certified-developer-foundations/mso-foundations/486742/scorm/1zuxexjatih0p)

### 1. Problem Statement

Describing a task using descriptive text alone often fails to unambiguously pin down the precise output structure, schema, or subtle stylistic constraints required by an enterprise application. Relying solely on abstract instructions can lead to unpredictable LLM output formats and schema variance in production workflows.

---

### 2. Summary

* **Prompting Modes Defined**: Prompting modes are defined by the number of worked input-output examples embedded directly inside the prompt context:
* **Zero-shot**: Provides task instructions without any worked examples.
* **One-shot**: Provides task instructions alongside exactly one input-output pair to anchor expected formatting.
* **Multi-shot (Few-shot)**: Incorporates multiple worked examples to demonstrate edge cases, complex output schemas, or subtle domain patterns.


* **In-Context Context vs. Training Data**: Worked examples sit strictly within the prompt context window to illustrate answer structure; they do not serve as training or fine-tuning data for model weights.
* **Output Shape Precision**: Worked examples demonstrate the exact expected shape, format, and structure of the desired answer, bridging gaps where text descriptions alone fall short.

---

### 3. Clear & Simple Explanation

Choosing a prompting mode is like giving instructions to a craftsman:

* **Zero-shot**: You describe what you want in words without showing any samples ("Build a wooden table"). The craftsman relies entirely on their past knowledge, which might lead to unexpected variations in style or dimensions.
* **One-shot**: You describe what you want and show a single sample ("Build a wooden table like this blueprint"). This anchors the basic design and format.
* **Multi-shot (Few-shot)**: You describe what you want and show several samples covering different styles ("Build a wooden table like these examples: standard dining, extensible multi-leaf, and compact side-table"). This shows how to handle different edge cases and guarantees exact structural consistency.

Because these examples sit inside the prompt during the request, they guide output formatting on the fly without permanently altering or retraining the model.

### 5. Key Terms Note Section

**Key Technical Terms**

* **Zero-shot Prompting**: A technique where a model is given instructions for a task without any input-output examples in the prompt.
* **One-shot Prompting**: A technique where a prompt includes instructions accompanied by exactly one worked example demonstrating the input and desired output.
* **Multi-shot (Few-shot) Prompting**: A technique where a prompt includes instructions accompanied by multiple worked examples demonstrating various input-output pairs and edge cases.
* **In-Context Examples**: Demonstration pairs placed directly inside the prompt payload to guide response generation without updating model weights.
* **Answer Shape**: The structural blueprint, schema, or formatting constraints of the model's output payload.

* A) Worked examples permanently alter the model's parameters through in-context fine-tuning.
* B) Worked examples sit entirely within the prompt context window to demonstrate output shape without modifying model weights.

* D) Multi-shot prompting requires pre-training the model on domain-specific datasets prior to issuing the API request.

2. An engineering team is designing a prompt for an API endpoint that must format erratic raw text into a complex nested JSON schema. Simple textual descriptions keep failing during automated integration tests. What is the most effective prompting strategy to resolve this formatting variance?

* A) Switch to zero-shot prompting and double the length of descriptive text.
* B) Retain zero-shot prompting but increase the API temperature parameter.
* C) Utilize multi-shot prompting by supplying multiple worked input-output pairs that explicitly demonstrate the nested schema and conditional edge cases.
* D) Use one-shot prompting with an empty JSON object as the input pair.

3. Which of the following represents a primary characteristic and trade-off of using a zero-shot prompting mode in a production LLM application?

* A) It minimizes input token overhead by providing only instructions, but relies heavily on the model's prior capabilities to infer expected output shape.
* B) It guarantees 100% deterministic JSON output formatting without requiring structural instructions.
* C) It consumes significantly more context tokens than multi-shot prompting while offering higher schema guarantees.
* D) It executes fine-tuning gradients on the prompt context before returning the output.

---

4. An architect is evaluating prompt design options. When transitioning from a one-shot prompt to a multi-shot prompt, what primary technical advantage does multi-shot provide for complex edge-case handling?

* A) It eliminates the need for system prompts altogether by embedding routing logic in the API headers.
* B) It drastically reduces input token consumption and API latency compared to one-shot prompts.
* C) It automatically validates output JSON payloads against an OpenAPI specification on the server side.
* D) It demonstrates multiple variations of input-output mappings, clarifying exact output shape across edge cases that a single example cannot capture.

---

5. A lead developer claims that descriptive text in a prompt is always sufficient to pin down complex output schemas, making worked examples unnecessary. According to the Claude Certified Developer curriculum, why is this premise flawed?

* A) Descriptive instructions are ignored by Claude models unless accompanied by system prompts.
* B) Worked examples are compiled into executable bytecode by the SDK before sending the request.
* C) Textual descriptions alone often fail to unambiguously pin down the exact shape and format of the desired output, which worked examples clearly illustrate.
* D) Multi-shot prompting is mandatory for all API requests to enable structured JSON outputs.

---

--- **Answer Key & Explanations** ---

1. **B** - Worked examples in multi-shot prompting sit inside the prompt context to guide answer formatting; they do not serve as training data or modify underlying model weights.
2. **C** - Multi-shot prompting provides multiple worked input-output examples, which explicitly demonstrate expected schemas and edge-case behavior when textual descriptions alone fail.
3. **A** - Zero-shot prompting passes only instructions, keeping input token costs low, but relies on the model to infer output formatting without concrete demonstration examples.
4. **D** - Multi-shot prompting allows developers to illustrate multiple input-output variations, clarifying structural requirements and edge cases that a single example cannot fully articulate.
5. **C** - Pure text descriptions frequently fall short when defining precise output shapes or complex schemas, whereas worked examples explicitly show the model the target format.
