## Model options and reasoning modes

### 1. Problem Statement

Architecting generative AI applications requires balancing execution speed (latency), operational cost, and cognitive power (capability). Developers often face the challenge of selecting the correct Claude model tier without over-engineering (incurring unnecessary cost and latency with overly large models) or under-engineering (causing application failure due to inadequate model intelligence).

### 2. Summary

The Claude model family spans four tiers, each addressing distinct trade-offs across cost, latency, and capability:

* **Fable**: The most capable tier, engineered for maximum intelligence, deep reasoning, coding, and demanding agentic tasks.
* **Opus**: Built for complex, highly demanding workloads exceeding Sonnet's capability threshold.
* **Sonnet**: The balanced, production-grade default suited for most standard enterprise workloads.
* **Haiku**: Built for maximum speed and cost efficiency on lighter tasks within its capability bounds.

**Core Technical Strategy:**

1. **Baseline Default**: Always start development and benchmarking using **Sonnet**.
2. **Tier Escalation**: Upgrade to **Opus** or **Fable** only when empirical evaluations (evals) demonstrate that Sonnet fails to meet required quality benchmarks.
3. **Tier Optimization**: Downgrade to **Haiku** only when evaluations confirm that any resulting drop in capability remains within acceptable limits for the task.
4. **Runtime Model Drift**: Always verify current model identifiers against `[platform.claude.com/docs](https://platform.claude.com/docs)` during system implementation.

---

### 3. Clear & Simple Explanation

Choosing the right Claude model is like selecting a vehicle for a delivery service:

* **Haiku** is a nimble motor scooter—extremely fast and cheap, ideal for quick, simple errands like sorting short messages or triaging tickets.
* **Sonnet** is a reliable sedan—it handles 80% of daily trips effortlessly with a balance of speed and fuel efficiency. It is your default starting choice.
* **Opus** is a heavy-duty transport truck—used when the payload requires extra horsepower that a standard sedan cannot carry.
* **Fable** is a specialized, high-performance machine—built for complex multi-stage tasks like autonomous programming and multi-agent coordination where top-tier problem-solving is essential.

Rather than guessing which model to pick, use test benchmarks (**evals**). Start with Sonnet. If test results show it isn't smart enough for your task, step up to Opus or Fable. If test results show Haiku achieves the exact same required outcome faster and cheaper, step down to Haiku.

### 4. Real-World Application

**Scenario: Intelligent Customer Support & Automated Code Patching Architecture**

An enterprise software platform receives customer issues ranging from simple account inquiries to critical code debugging requests. To optimize performance and API expenditure, the system employs an evaluation-driven model routing architecture:

```
                  [ Incoming User Request ]
                             │
                             ▼
              [ API Gateway & Router Service ]
                             │
            ┌────────────────┴────────────────┐
            ▼                                 ▼
   (Intent Classification)         (Standard Support / Q&A)
   Model: Claude Haiku             Model: Claude Sonnet
   • Low Latency                   • Default Tier
   • Cheap Triage                  • Balanced Quality & Speed
            │                                 │
            └────────────────┬────────────────┘
                             │
                             ▼
                [ Code Remediation Needed? ]
                             │
                     ───────┴───────
                    │ Yes           │ No
                    ▼               ▼
           [ Complex Agent ]  [ Complete Request ]
            Model: Fable
            • Deep Reasoning
            • Agentic Execution

```

**Workflow Breakdown:**

1. **Fast Triage (Haiku)**: The incoming request is analyzed for intent classification and sentiment within milliseconds.
2. **Standard Processing (Sonnet)**: Basic queries, documentation search, and response generation are routed to Sonnet by default.
3. **Complex Engineering Tasks (Fable)**: If an issue requires multi-step autonomous tool use, code generation, or complex debugging, the system escalates execution to Fable to ensure peak reasoning capacity.

---

### 5. Key Technical Terms

* **Fable**: The top-tier Claude model family member engineered for maximum reasoning capacity, complex coding, and autonomous agentic workflows.
* **Opus**: A high-capability Claude tier designed to handle demanding tasks that fall outside Sonnet's capability envelope.
* **Sonnet**: The practical baseline default model tier offering a balanced trade-off between performance, cost, and latency for standard production workloads.
* **Haiku**: The lightweight, ultra-fast model tier optimized for low latency and high cost efficiency on streamlined tasks.
* **Evaluation (Eval)**: Quantitative, empirical testing used to evaluate model outputs against defined quality bars to determine appropriate model tiering.
* **Capability Envelope**: The threshold of task complexity and cognitive demand that a specific model tier can reliably satisfy without quality degradation.

* A) Start initial implementation with Fable to establish maximum baseline quality, then move down to Haiku once prompts are frozen.

4. During performance optimization of an automated document processing pipeline currently running on Sonnet, an engineer proposes switching the workload to Haiku. According to Claude certification standards, what condition must be satisfied before deploying this change to production?

* A) The application logic must be rewritten to run asynchronously.
* B) An evaluation (eval) must demonstrate that the quality drop on Haiku is within acceptable limits for the task.
* C) The model identifiers must be hardcoded into client software without doc verification.
* D) The service must experience consecutive rate-limiting events on Sonnet.

---

--- **Answer Key & Explanations** ---

1. **B** - Sonnet serves as the practical default for production workloads. Developers should escalate to higher tiers (Opus/Fable) only when evaluations prove Sonnet falls short of quality thresholds, and downgrade to Haiku only when evaluations confirm acceptable output quality.
2. **D** - Fable is the most capable tier within the Claude model family, specifically built for maximum intelligence across deep reasoning, coding, and demanding agentic tasks.
3. **A** - Haiku is engineered specifically for tasks fitting its capability envelope where speed (low latency) and cost efficiency are the primary operational requirements.
4. **B** - Moving down a tier to Haiku should only occur after empirical evaluations (evals) confirm that any potential drop in output quality remains acceptable for the specific business task.
