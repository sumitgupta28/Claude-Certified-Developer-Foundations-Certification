--- ANSWER KEY ---

Question 1: C

Explanation: An oversized prompt that exceeds the context window limit before generation starts triggers an immediate validation/API error prior to model processing.

Question 2: A

Explanation: Hitting the context window ceiling mid-generation returns `stop_reason: "model_context_window_exceeded"`. Because the model context window is fixed, managing conversation history via pruning or truncation is the application's responsibility.

Question 3: D

Explanation: Sampling temperature causes non-deterministic output generation, making exact text matching fragile. Model capabilities and prompt changes should be measured using systematic evaluations (evals).

Question 4: B

Explanation: Model selection and reasoning modes are composable levers. Best practices dictate starting with the smallest model and simplest prompting strategy that satisfies your eval suite, escalating capability only when evals require it.

Question 5: C

Explanation: The Message Batches API is purpose-built for bulk, non-interactive offline processing, offering high throughput and reduced token costs within a 24-hour turnaround window.

Question 6: C

Explanation: The official Anthropic SDKs automatically inject required headers (such as `x-api-key` and `anthropic-version`) and execute exponential backoff retries for transient HTTP errors (e.g., 429, 5xx), which raw REST implementations require developers to write manually.

Question 7: A

Explanation: In an SSE streaming architecture, the client application is responsible for consuming incremental stream event fragments, reassembling them into the complete payload, and managing network reconnections or interruptions.

Question 8: B

Explanation: The official Python SDK exposes a distinct `AsyncAnthropic` class for `async/await` non-blocking operations, whereas the TypeScript SDK is built natively on Promises directly on its core client without a separate async class.
